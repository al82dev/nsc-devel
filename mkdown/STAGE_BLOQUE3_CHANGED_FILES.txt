    tanto como su objeto y ese objeto no tiene relacion con el duenno de lo prestado: no hay dos

HUECOS DEL LENGUAJE ENCONTRADOS AL ESCRIBIR ESTO -- MEDIDOS, ANOTADOS, NO ARREGLADOS
-----------------------------------------------------------------------------------
ID 131  Un miembro estatico de un tipo generico CERRADO no se puede nombrar.
            Box<int>.Make(1)     -> "expected expression" / "expected ';', found 'Make'"
            Helper.Wrap<int>(1)  -> compila
        Cerrarlo pide que el modelo de nombres resuelva una instanciacion generica en posicion de
        EXPRESION y que el modelo generico la monomorfice desde ahi. Es de otro bloque.
        CONSECUENCIA VISIBLE: las fabricas viven en `Spans` y `Optionals` en vez de dentro de los
        structs. Cuando el ID se cierre, se mudan sin tocar nada mas.

ID 132  Dos metodos genericos con el mismo nombre y la misma aridad de tipos no se sobrecargan:
            duplicate generic template identity 'NativeSharp.Core.Spans.Of``1'
        La identidad es nombre + numero de parametros de tipo, sin la lista de parametros. Por eso
        hay `OfRange` y no un segundo `Of`.

ID 130  `applyUwtableAttribute` pide `uwtable` con valor 0. En LLVM el valor es un UWTableKind:
        0 = None, 1 = Sync, 2 = Async. CERO SIGNIFICA "SIN TABLA", lo contrario de lo que el
        nombre promete. Medido con la propia LlvmCApi.h del proyecto sobre LLVM 18: con 0 el
        modulo impreso sale TRUNCADO A 65 BYTES y con basura desde el primer atributo; con 2
        imprime correcto. En Windows x64 la tabla de desenrollado es lo que SEH necesita.
        NO SE TOCA AQUI: cambiar los atributos de todas las funciones es una decision del proyecto
        con su medicion en Windows, no un efecto colateral del Bloque 3.
