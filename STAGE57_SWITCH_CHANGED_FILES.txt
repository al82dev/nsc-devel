AST

include/nativesharp/AST/AstNodeKind.h
    + SwitchStatement
    + SwitchSection
    + SwitchLabel

src/AST/AstNodeKind.cpp
    + NS_AST_KIND para los tres

Forma de los nodos:
    SwitchStatement  first()        = expresion gobernante
                     children()     = secciones, en orden de fuente
    SwitchSection    children()     = etiquetas primero, statements despues
                     integerValue() = cuantas children son etiquetas
    SwitchLabel      first()        = expresion constante, o nullptr si es default
                     flag()         = true si es default

El contador explicito de etiquetas evita que cualquier consumidor tenga que
decidir "etiqueta o statement" inspeccionando kinds -- ese tipo de decision deja
de funcionar en silencio cuando se agrega un kind de statement nuevo.

src/Parser/Parser.cpp
    + atSwitchLabel()
        `case` siempre abre etiqueta. `default` SOLO si el token siguiente es `:`
        -- si no, una seccion que empiece con `default(int)` se leeria como
        etiqueta y el parser se perderia.
    + parseSwitchStatement()
        - `switch` `(` expr `)` `{` seccion* `}`
        - una seccion es: etiqueta+ statement*
        - los statements corren hasta la siguiente etiqueta o hasta `}`
        - un token que no abre etiqueta al inicio de una seccion produce
          diagnostico Y se consume, para que el bucle avance
        - la expresion de un `case` se parsea como expresion completa; que sea
          constante y que convierta al tipo gobernante son preguntas semanticas
    + gancho en parseStatement:
        if (at(TokenKind::KwSwitch)) return parseSwitchStatement();

src/LLVM/ProjectOopLlvmLowerer.cpp
    ~ struct LoopTargets gana `continueFuncletDepth`
        Un marco de switch lleva su propio destino de break pero el destino de
        continue DEL BUCLE QUE LO ENCIERRA, y los dos pueden estar a
        profundidades de funclet distintas. Con una sola profundidad, un break
        desenrollaria funclets que no debe o un continue se saltaria funclets que
        si debe.
    ~ los tres push de loopStack_ (while / do-while / for) pasan la cuarta
      profundidad explicitamente
    ~ lowerStructuredExit: elige funcletDepth para break y continueFuncletDepth
      para continue; falla explicitamente si un continue llega sin destino
    + lowerSwitch()
        Una sola LLVMBuildSwitch. Un bloque por seccion + switch.end.
        Sin `default`, el destino por omision del switch es switch.end.
        Cada bloque de caso termina ramificando a switch.end -- la ausencia de
        fall-through se ve en el layout de bloques.
        El marco que empuja hereda continueTarget del bucle que lo encierra.
        La constante de cada caso usa el mismo criterio de signo que el lowering
        de campos constantes (un enum baja a i32 y sus miembros son con signo).
        El guard de "esto es un entero" se expresa sobre la CLAVE DE TIPO
        (isEnumTypeKey || ProjectTypeConversion::isIntegral) en vez de probar el
        tipo de LLVM con LLVMGetTypeKind, para no fijar el enum LLVMTypeKind con
        valores numericos en un header nuestro.
    + dispatch: case Switch -> lowerSwitch
    + dispatch: case SwitchSection -> error explicito
        ("a switch section must be lowered by its enclosing switch")
