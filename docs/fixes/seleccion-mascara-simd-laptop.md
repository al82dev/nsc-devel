# Selección por máscara SIMD: lote de laptop

## SCOPE LOCK

- Objetivo: permitir `mask<T,N> ? a : b` cuando `a` y `b` son valores SIMD o máscaras idénticos con el mismo tipo y número de lanes que la condición. Resultado por lane: el de `a` si el lane de condición es verdadero, el de `b` si es falso.
- Contrato: se evalúan una vez y en ese orden condición, primer valor y segundo valor; ambos valores se evalúan para poder seleccionar lanes mezclados. El condicional escalar `bool ? a : b` conserva su evaluación perezosa y análisis de ownership existentes. Las ramas SIMD deben tener tipo y cantidad exactos; incompatibilidades reciben diagnóstico.
- Base: `6c6e33b85`, rama `development-fixes-limitaciones-laptop`; referencia publicada del colega `08d5e3069`, no integrada. El usuario autorizó continuar SIMD cuidando el trabajo de su colega. `OperatorAndConditionalExpressions.cpp` coincide por archivo con un cambio publicado suyo en `??`; esta corrección se restringe a `?:` con condición máscara. No se cambian sus reglas de préstamos, seguridad o SDK binario; se registra la necesidad de validación conjunta al integrar.
- Ruta causal: el frontend rechaza la condición porque no es `bool` y analiza las ramas como alternativas. La representación HIR/MIR actual ya transporta los tres operandos; LLVM genera una rama escalar. Para máscaras, el frontend debe analizar los operandos secuencialmente y el backend producir una selección vectorial; para `bool` debe conservar las rutas existentes.
