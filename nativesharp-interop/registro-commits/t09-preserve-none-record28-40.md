# Registros C++ de 28 y 40 bytes preserve_none

Se habilitan funciones `preserve_none` que reciben y devuelven el mismo registro C++ trivial de 28 o 40 bytes. Las muestras contienen siete y diez campos `int`, respectivamente. Clang 23.1.0 usa retorno `sret` y argumento indirecto alineados a cuatro; las pruebas comprueban todos los campos y la copia. El control C++ de 40 bytes incluye una rutina auxiliar `memcpy` porque se enlaza sin CRT.

Los fixtures `pruebas-tanda-09-preserve-none-record28` y `pruebas-tanda-09-preserve-none-record40` pasaron, cada uno, ocho comparaciones Clang/NativeSharp directas y por puntero en estática y DLL O0–O3 (`A:/temp/nsc-t09-preserve-cpp-record24-pcw5yyqt` y `A:/temp/nsc-t09-preserve-cpp-record24-3214jxmp`). Cada uno pasó dieciséis consumidores precompilados con y sin encabezado (`A:/temp/nsc-t09-preserve-cpp-record24-precompilado-39hn9xuq` y `A:/temp/nsc-t09-preserve-cpp-record24-precompilado-j50majjy`). La compilación incremental agrupada pasó. La prueba de rechazo se conserva para la forma aún no implementada de 44 bytes (`A:/temp/nsc-t09-preserve-none-record-negativo-1qqk7nmz`).

Las muestras corresponden a Windows x64 y no certifican todos los layouts ni otros tamaños. El inventario y NSMeta aún no conservan un plan ABI `preserve_none` general; esa dependencia impide convertir una lista de tamaños en soporte general. Las clases no triviales, variádicas y TLS aislado siguen pendientes; T09-003 y la tanda 9 permanecen abiertos.
